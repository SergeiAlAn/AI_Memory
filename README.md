# Telegram-бот с двумя типами памяти

Универсальный AI-помощник в Telegram, у которого есть **короткая память** (история диалога) и **долгая память** (загруженный документ, превращённый в эмбеддинги).

Пользователь загружает документ с описанием роли помощника и нужной информацией. Бот принимает эту роль и отвечает на вопросы, опираясь на документ и на историю переписки. Новый документ полностью меняет роль и базу знаний.

## Возможности

- Ответы через модель `openai/gpt-4o-mini` (ProxyAPI).
- Загрузка документов **PDF, TXT, DOCX** (до 20 МБ — ограничение Telegram).
- Автоматическое определение роли помощника по содержимому документа.
- Ответы строго по документу: если информации нет, бот так и говорит, а не выдумывает.
- У каждого пользователя своя роль, своя история и своя база знаний.

## Стек

| Библиотека | Зачем |
| --- | --- |
| `aiogram` 3.x | Асинхронный Telegram-бот (обработчики команд, текста и файлов) |
| `openai` | Клиент для ProxyAPI (OpenAI-совместимый API): чат и эмбеддинги |
| `chromadb` | Локальная векторная база с хранением на диске (`./memory`) |
| `pypdf` | Извлечение текста из PDF |
| `python-docx` | Извлечение текста и таблиц из DOCX |
| `python-dotenv` | Загрузка токенов из файла `.env` |

Модели ProxyAPI (endpoint `https://api.proxyapi.ru/v1`):
- `openai/gpt-4o-mini` — генерация ответов и определение роли;
- `openai/text-embedding-3-small` — эмбеддинги (сама `gpt-4o-mini` эмбеддинги не создаёт).

## Как устроена память

### Короткая память (history buffer)

- **Где хранится:** в оперативной памяти процесса, в словаре `short_memory: dict[user_id -> deque]`.
- **Объём:** последние **10 сообщений пользователя и 10 ответов бота**. Используется `deque(maxlen=20)`: при добавлении новой записи самая старая удаляется автоматически.
- **Формат записи:** `{"role": "user" | "assistant", "content": "..."}` — сразу в том виде, в каком её ждёт Chat Completions API.
- **Когда очищается:**
  - командой `/reset`;
  - при загрузке нового документа (новая роль — новый диалог, чтобы старая история не противоречила роли);
  - при перезапуске бота (память живёт только в RAM).

Короткая память нужна, чтобы бот понимал уточняющие вопросы: «а сколько это стоит?», «расскажи подробнее про второй пункт».

### Долгая память (документ → эмбеддинги)

- **Где хранится:** в ChromaDB, папка `./memory` (persistent storage — переживает перезапуск). Исходные файлы сохраняются в `./documents/<user_id>/`.
- **Структура:** у каждого пользователя своя коллекция `user_<id>`. В ней:
  - фрагменты (чанки) документа и их векторы;
  - метаданные фрагментов: имя файла и номер чанка;
  - метаданные коллекции: **роль** помощника и имя исходного файла. Поэтому роль тоже сохраняется после перезапуска.
- **Метрика поиска:** косинусное расстояние (`hnsw:space = cosine`).

Как документ попадает в долгую память:

1. **`load_document()`** — читает PDF / TXT / DOCX и разбивает текст на чанки ≈ **500 символов** с перекрытием 100 символов. Разрез делается по границе абзаца, предложения или слова, чтобы не рвать мысль. Для TXT автоматически подбирается кодировка (UTF-8 или cp1251).
2. **Определение роли** — первые ~4000 символов документа отправляются в `gpt-4o-mini` с просьбой сформулировать системную инструкцию «Ты — …». Если роль описана в документе явно, она сохраняется максимально точно; если нет — модель выводит роль эксперта по теме документа.
3. **`embed_chunks()`** — получает эмбеддинги чанков пачками по 100 штук, удаляет старую коллекцию пользователя и создаёт новую с чанками, векторами и ролью.

## Логика обработки запроса

Когда пользователь пишет сообщение, вызывается **`answer_question()`**:

1. Достаёт роль пользователя из метаданных коллекции (если документа нет — роль по умолчанию «универсальный помощник»).
2. **`retrieve_context()`** — превращает вопрос в эмбеддинг и находит в ChromaDB **4 самых близких фрагмента** документа.
3. Собирает запрос к модели:
   - `system` — роль + найденные фрагменты + правила: отвечать строго по фрагментам, честно говорить «в документе этого нет», учитывать историю диалога;
   - история из короткой памяти (до 20 записей);
   - текущее сообщение пользователя.
4. Отправляет запрос в `gpt-4o-mini` (temperature 0.3 — меньше фантазии, больше точности).
5. Добавляет вопрос и ответ в короткую память и отправляет ответ пользователю (длинные ответы разбиваются на части по 4096 символов).

```
Сообщение пользователя
        │
        ├──► короткая память (последние 10 пар «вопрос + ответ»)
        │
        ├──► эмбеддинг вопроса ──► ChromaDB ──► 4 релевантных фрагмента
        │
        ▼
 system (роль + фрагменты + правила) + история + вопрос ──► gpt-4o-mini
        │
        ▼
 Ответ ──► пользователю и в короткую память
```

Если документ не загружен, бот работает как обычный чат-помощник только с короткой памятью.

Синхронные операции (ChromaDB, парсинг PDF) выполняются через `asyncio.to_thread`, чтобы не блокировать обработку сообщений других пользователей.

## Команды бота

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Справка |
| `/upload` | Подсказка, как загрузить документ |
| `/role` | Показать текущую роль помощника |
| `/reset` | Очистить короткую память (документ и роль сохраняются) |
| `/forget` | Удалить документ из долгой памяти и вернуться к роли по умолчанию |
| *отправка файла* | Загрузить новый документ (заменяет предыдущий вместе с ролью) |

## Установка и запуск

Нужен Python 3.10+.

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`:

```env
BOT_TOKEN=токен_от_BotFather
PPROXY_API_KEY=ключ_ProxyAPI
```

Запуск:

```powershell
python bot_two_types_of_memory.py
```

